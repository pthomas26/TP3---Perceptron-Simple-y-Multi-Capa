## Notebooks Overview

### Notebook 0 — Validation

> *"Before shipping anything to CompanyX, we need to be confident our tools work correctly."*

Validates each perceptron variant on simple, well-understood problems where the expected answer is known. Think of it as unit-testing the neural network implementation.

| Model | Problem | Expected result |
|---|---|---|
| Step Perceptron | AND gate | Converges to 0 errors |
| Linear Perceptron | y = x | Fits the regression line |
| Non-linear Perceptron | y = tanh(x) | Fits the non-linear shape |
| MLP [2,2,1] | XOR | Solves non-linearly separable problem |
| MLP [2,3,2,1] | XOR | Deeper architecture, richer boundary |

**Key insight validated here:** the step perceptron cannot solve XOR — it can only draw one hyperplane. This directly motivates the MLP for Exercise 2.

### Notebook 1 — Exercise 1: Fraud Detection (Knowledge Distillation)

> *"CompanyX has a BigModel that is accurate but expensive. We build TinyModel to imitate it."*

**The problem:** instead of training on binary fraud labels, we train on the soft probabilities already computed by BigModel. This is **Knowledge Distillation** — the target column `big_model_fraud_probability` contains values in [0, 1].

#### Exploratory Data Analysis

- 7,500 transactions, 9 input features, target in [0, 1]
- **Class imbalance:** only 11.6% fraud → plain accuracy is misleading
- **Target is quasi-binary:** BigModel is very confident, true soft probabilities are rare
- `timestamp` is a raw Unix integer — kept as-is, flagged as a limitation

#### Learning Capacity Study

Both perceptrons are trained on the full dataset to isolate model capacity from generalization:

| Model | MSE (full data) | Verdict |
|---|---|---|
| Linear Perceptron | 0.0292 | Underfits — SSE stagnates after epoch 2,000 |
| Non-linear (sigmoid) | 0.0202 | Selected — SSE still decreasing at epoch 5,000 |

**Why sigmoid?** Its output is naturally bounded in (0, 1), matching the fraud probability target. The linear perceptron can produce values outside [0, 1], making threshold selection meaningless.

#### Generalization Study

**Strategy:** 5-fold cross-validation with train-only normalization at each fold (no data leakage).

**Why 5-fold and not a simple split?** 7,500 samples is limited — a fixed split gives one unreliable estimate. 5-fold uses every sample once as validation, producing a statistically robust mean ± std.

**Why these metrics?**
- **MSE** — measures distillation quality: how close are our predictions to BigModel?
- **ROC-AUC** — threshold-independent ranking ability
- **PR-AUC** — more informative than ROC-AUC when classes are imbalanced (11.6% fraud)

**Results — 10 independent runs × 5-fold CV:**

| Metric | Mean | Std |
|---|---|---|
| MSE | 0.0204 | ± 0.0001 |
| ROC-AUC | 0.9931 | ± 0.0003 |
| PR-AUC | 0.9677 | ± 0.0009 |

The near-zero standard deviations across 10 independent runs confirm that results are robust — not a lucky initialization.

#### Threshold Recommendation

Our model outputs a probability. CompanyX needs a decision rule.

**Trade-off:**
- Low threshold → high recall (catch more fraud), but more false alerts (costly manual reviews)
- High threshold → high precision (fewer false alerts), but miss more fraud (direct losses)

**Method:** maximize the F1-score (harmonic mean of precision and recall) across all possible thresholds.

| Parameter | Value |
|---|---|
| Recommended threshold | **0.475** |
| F1-score | 0.916 |
| Precision | 96.9% |
| Recall | 86.8% |

> Flag any transaction with score > 0.475. Adjust up if manual review cost dominates; adjust down if fraud losses dominate.

### Notebook 2 — Exercises 2 & 3: Digit Classification

> *"A single perceptron was enough for a scalar fraud probability. It cannot classify 10 digit classes — this is fundamentally not linearly separable."*

#### Why the MLP?

The step perceptron on XOR (2 classes, 2 features) already fails — it can only draw one hyperplane. Classifying digits 0–9 from 784-pixel images requires a **Multilayer Perceptron** with:
- **tanh** hidden layer activations
- **Softmax** output layer (proper probability distribution over 10 classes)
- **Cross-entropy loss** (penalizes confident wrong predictions more than SSE)
- **Backpropagation** (chain rule propagated through all layers)

#### Exercise 2 — EDA: A Critical Discovery

| Finding | Impact |
|---|---|
| Digit 8: **0 training samples** | Any 8 in the test set will be misclassified — guaranteed |
| Digit 5: **271 samples** vs ~1,500 for others | 6× imbalance → weaker generalization on 5s |

These two observations explain the Exercise 2 test accuracy before a single model is trained.

#### Exercise 2 — Systematic Hyperparameter Exploration

**Validation strategy:** 5-fold CV grid search on `digits.csv` only. `digits_test.csv` was never touched during this phase — it represents production conditions.

**Learning rate** (architecture fixed at [784, 64, 10]):

| LR | Val Accuracy | Observation |
|---|---|---|
| 0.1 | 0.960 ± 0.005 | Best — fast convergence |
| 0.01 | 0.944 ± 0.004 | Stable but lower ceiling |
| 0.001 | 0.908 ± 0.008 | Hasn't converged in 50 epochs |
| 0.0001 | 0.821 ± 0.013 | Too slow — high variance |

**Architecture** (lr=0.1 fixed):

| Architecture | Val Accuracy | Observation |
|---|---|---|
| [784, 32, 10] | 0.953 ± 0.003 | Too shallow |
| [784, 64, 10] | 0.962 ± 0.004 | Good single layer |
| [784, 128, 10] | 0.961 ± 0.003 | Wider but same depth |
| **[784, 128, 64, 32, 10]** | **0.964 ± 0.002** | **Best — depth helps, lowest variance** |

**Optimization** (best lr + best arch fixed):

| Optimizer | Val Accuracy | Observation |
|---|---|---|
| **SGD** | **0.965 ± 0.003** | **Best — simple and stable** |
| Momentum 0.9 | 0.946 ± 0.007 | lr=0.1 + momentum destabilizes |
| Momentum 0.95 | 0.114 ± 0.007 | **Diverges from epoch 1** — lr too high |
| LR Decay 0.99 | 0.963 ± 0.002 | Stable — lowest std |

**Why does Momentum 0.95 diverge?** At lr=0.1, SGD already takes large steps. Momentum=0.95 carries 95% of past velocity, amplifying each step too aggressively — the effective step size explodes and the loss diverges from the very first epoch.

#### Exercise 2 — Test Set Results

**Best configuration:** [784, 128, 64, 32, 10] + lr=0.1 + SGD

| Metric | Value |
|---|---|
| Test accuracy | **86.70%** |

**Confusion matrix analysis:**
- Digit 8: 0/~250 correct — confused with 3 (69×), 5 (56×), 2 (28×). Never seen in training.
- Digit 5: 192/223 correct (86%) — consequence of only 271 training samples.
- Digits 0–4, 6–7, 9: all above 96% per-class accuracy.

**Conclusion:** the architecture is sound. The bottleneck is data — specifically the absence of digit 8 and the underrepresentation of digit 5.

#### Exercise 3 — More Data Changes Everything

CompanyX collected additional data: `more_digits.csv`. Combined with the original dataset and Gaussian noise augmentation (noise_std=0.05, factor=1):

| | Exercise 2 | Exercise 3 |
|---|---|---|
| Digit 8 samples | 0 | 585 |
| Digit 5 samples | 271 | 813 (3×) |
| Total samples | 12,449 | 56,380 (+ augmentation) |
| Test accuracy | 86.70% | **96.56% ± 0.17%** |

**Techniques used:**
1. Combined `more_digits.csv` with `digits.csv` (28,190 samples)
2. Gaussian noise augmentation noise_std=0.05, factor=1 (56,380 total)
3. ~~Targeted augmentation factor=3 on digits 5 & 8~~ → **96.20% — WORSE.** Over-augmenting re-imbalanced the dataset in reverse.

#### Exercise 3 — Attempts to Reach 98%

| Attempt | Config | Result | Verdict |
|---|---|---|---|
| Baseline | [784,128,64,32,10] + SGD | **96.56% ± 0.17%** | Reference |
| Targeted augmentation (factor=3) | Same arch | 96.20% | Worse — single run |
| Lower lr (0.01 + momentum + decay) | Same arch | 96.64% | Marginal — single run |
| Larger architecture [784,256,128,64,10] | Same optimizer | **96.72% ± 0.27%** | Marginal — 5-run analysis |

The larger architecture achieves a slightly higher mean (+0.16pp) but with greater variance (±0.27% vs ±0.17%). The confidence intervals overlap — the two architectures are statistically equivalent. **The bottleneck is data quantity on digit 5, not model capacity.**

#### Exercise 3 — Statistical Robustness

5 independent runs with different random seeds confirm reproducibility:

| Metric | Value |
|---|---|
| Mean test accuracy | **96.56%** |
| Standard deviation | **± 0.17%** |
| Gain vs. Exercise 2 | **+9.86 percentage points** |

The near-zero variance proves results are not a lucky initialization. Note: only 5 runs (vs 10 for Exercise 1) due to the significantly larger dataset size — each run takes approximately 10 minutes.

## Implementation Notes

### Models implemented from scratch (NumPy only)

| Class | File | Description |
|---|---|---|
| `StepPerceptron` | notebook_00 | Rosenblatt learning rule |
| `LinearPerceptron` | notebook_00/01 | ADALINE, delta rule (Widrow-Hoff) |
| `NonLinearPerceptron` | notebook_00/01 | sigmoid/tanh/relu, chain rule update |
| `MLP` | notebook_00 | Backpropagation, arbitrary architecture |
| `MLPClassifier` | notebook_02 | Vectorized, mini-batch, momentum, LR decay, softmax + cross-entropy, save/load |

### Key design decisions

**Normalization:** always computed on the training set only, then applied to validation/test. This prevents data leakage — a common source of overly optimistic results.

**Model persistence:** `MLPClassifier.save()` and `.load()` allow resuming long experiments without restarting from scratch.

**Experiment logging:** all hyperparameter configurations are logged to `EXPERIMENT_LOG` with mean ± std, training time, and a reference to the best model. Analysis (plots, tables) is performed separately from training.

**Variance reporting:** stochastic processes (random initialization, mini-batch shuffle) are reported with mean ± std over multiple independent runs. Single-run results are flagged as exploratory.

## Key Lesson

> Every meaningful performance gain across all three exercises came from **better data**, not a better model. Architecture and hyperparameters matter at the margin, but data quantity and quality dominate.

- Ex1: a single perceptron achieves ROC-AUC 0.993 — the problem was well-conditioned.
- Ex2 → Ex3: +9.86 percentage points gained exclusively from adding more data. The architecture did not change.
- A larger architecture [784, 256, 128, 64, 10] is statistically equivalent to the baseline — adding capacity does not help when data is the constraint.
